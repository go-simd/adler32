# fletcher4

The ZFS **fletcher4** block checksum with SIMD kernels, bit-identical to OpenZFS
`fletcher_4_native` (`module/zcommon/zfs_fletcher.c`, `fletcher_4_scalar_native`).

```go
import "github.com/go-simd/adler32/fletcher4"

sum := fletcher4.Sum(block) // [4]uint64{a, b, c, d}, little-endian ("native") words
```

Per little-endian 32-bit word `w`: `a += w; b += a; c += b; d += c`, all mod 2^64.
A trailing partial word is ignored, as in OpenZFS.

| arch | kernel | lanes |
|---|---|---|
| amd64 | AVX-512 (`VPMOVZXDQ` + `VPADDQ`, runtime dispatch) | 8 |
| amd64 | AVX2 | 4 |
| arm64 | NEON (`UXTL`/`UXTL2` + `ADD`) | 4 (two 2-lane sets) |
| others | scalar loop | n/a |

Lane `j` sums the words `j, j+L, j+2L, ...`; the lanes are folded with the
closed forms OpenZFS uses in its `fini` functions (`zfs_fletcher_intel.c`,
`zfs_fletcher_avx512.c`, `zfs_fletcher_aarch64_neon.c`). Here the integers are
solved exactly at init (`solveCoefs`) and a test checks them against the three
OpenZFS `fini` functions transcribed verbatim. The kernels are generated by
[go-asmgen](https://github.com/go-asmgen/asmgen) (`internal/gen`, its own module
so this module gains no dependency): `cd internal/gen && go run .`.

## Verification

- `TestScalarEqualsOpenZFSScalar`, `TestSumEqualsOracle`, `TestSumWrap`,
  `TestEveryKernel`: every kernel against a transcription of the OpenZFS scalar
  loop, on lengths 0 to 700 (with misaligned starts) and up to 1 MiB.
- `TestFoldEqualsOpenZFSFini`: the lane fold against the OpenZFS AVX2, AVX-512
  and NEON `fini` formulas, for arbitrary accumulators.
- `TestKernelsStayInsideTheBuffer`: the buffer ends against a `PROT_NONE` page.
- `FuzzSum`: 26 million executions in 20 s, no difference.
